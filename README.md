# BTC / ETH 日线趋势跟踪顾问

每晚北京时间 21:00 运行一次，输出"今天该买 / 卖 / 拿住"以及目标仓位、金额、止损位。

## 一、安装 (一次性)

```bash
pip install -r requirements.txt
```

需要 Python 3.9+。数据源：OKX（主）→ Coinbase（备），国内网络一般可直连 OKX；不行就开代理。
首次运行会把 2018 年至今的日线缓存在 `data/`，之后每天只增量拉几根。

## 二、每天怎么用

```bash
python advisor.py            # 输出今日建议，同时写入 reports/advice_YYYY-MM-DD.md 和 reports/latest.md
python advisor.py backtest   # 看 2020 年至今回测
python advisor.py both
```

定时任务：
- Linux/Mac：`crontab -e` 加 `0 21 * * * /bin/bash /你的路径/crypto_advisor/run.sh >> /你的路径/crypto_advisor/reports/cron.log 2>&1`
- Windows：任务计划程序 → 每天 21:00 → 运行 `run.bat`

**为什么是 21:00**：币圈日线以 UTC 0 点收盘 = 北京时间早 8 点。晚上 9 点跑时，用的是早上 8 点已经收完的那根 K，信号一天只变一次，不会盘中漂移。你跑完在晚上或第二天早上下单都可以。

## 三、把"本金"和"实际仓位"告诉程序

第一次运行会生成 `config.json`：

```json
"capital_per_coin_usdt": {"BTC": 10000, "ETH": 10000}
```
改成你分配给每个币的总本金（USDT），报告里的买卖金额就会按这个算。

`state.json` 里的 `current_pct` 是程序**假定你已按建议执行后**的仓位。如果你没照做（比如它让你减到 50% 你没减），请手动把这个数改成真实仓位，第二天的建议才准确。

## 四、策略是怎么"学"出来的 (research.py, 完整数据见 reports/research_report.md)

不是拍脑袋定的。流程:

1. **候选池**: 6 个策略族、308 组参数 —— 单均线过滤 (50~300 日)、均线缓冲带、EMA 金叉、唐奇安突破、动量 ROC、多指标评分状态机 (v1 用的那套)。
2. **样本内 / 样本外**: 用 2020~2023 选参数，拿 2024~今 检验。避免"先看答案再做题"。
3. **滚动前推**: 每年只用当年之前的数据选最优，用到下一年，拼出一条"当年真实可得"的曲线。
4. **参数邻域**: 看最优点旁边的参数是否也好。孤峰 = 过拟合。

**学到了什么 (含打脸自己的部分)**:

| 发现 | 证据 |
|---|---|
| v1 的 8 分打分状态机**没有优势** | 225 组参数里样本外 Calmar 中位数 0.64 (BTC) / 0.24 (ETH)，不如简单均线族；阈值越多越容易拟合历史 |
| 单条均线的最优周期**在两个币上完全不同** | BTC 最优 SMA110，ETH 最优 SMA280 → 说明"最优周期"是噪声，不能信 |
| 单一均线**参数敏感** | BTC: SMA110 回撤 −29%，旁边的 SMA80 回撤 −52%，SMA200 回撤 −64%。孤峰 |
| 但**均线这个族整体稳健** | 26 组单均线里 85~88% 在样本外跑赢持有；这是全部 6 族里最一致的 |
| 滚动前推选出来的策略年年在换 | BTC: ROC30→SMA50→SMA110；ETH: ROC30→DC20/10→ROC30。追"上一年最好的"不靠谱 |

**结论**: 既然"均线过滤"整体有效但"哪一条"不可知 → 不选，全用。**7 条 SMA (50/75/100/125/150/175/200) 投票**，收盘在几条之上就拿几分之几仓位，量化到 25% 一档。等距覆盖、无阈值可调，是候选里过拟合风险最低的方案。

## 五、最终策略与回测 (2020-01-01 ~ 2026-09-20, 含 0.1% 手续费)

**规则**: 每天收盘后数收盘价在 7 条均线里几条之上 → 目标仓位 = 票数/7 → 量化到 0/25/50/75/100%，变动不足 25% 不动。就这一条。

| | BTC 策略 | BTC 持有 | ETH 策略 | ETH 持有 |
|---|---|---|---|---|
| 总收益 | +1243% | +1028% | +1942% | +1947% |
| 年化 | 47% | 43% | 57% | 57% |
| **最大回撤** | **−49%** | **−77%** | **−56%** | **−79%** |
| 夏普 | 1.16 | 0.91 | 1.07 | 0.97 |
| 样本外 (2024~) Calmar | 1.01 | 0.51 | 0.86 | 0.08 |
| 调仓次数 | 145 (~21 次/年) | — | 130 | — |
| 平均仓位 | 57% | 100% | 57% | 100% |

分年: 2022 熊市 BTC −20% (持有 −64%)，ETH −30% (持有 −68%)；2025 震荡年 BTC +4% / ETH +24% (持有均为负)。牛市年份跑输持有是必然的，那是保险费。

**怎么读**:
1. 这次年化没输给持有，同时回撤少 25 个百分点 —— 但请把年化看作运气成分较大、回撤降低看作策略的真实价值。
2. 21 次/年的调仓多数是 25% 的小幅加减，不是全进全出。嫌多可把 `config.json` 里 `step_pct` 改成 50 (调仓降到 ~8 次/年，BTC 回撤 −44%，ETH 会略差)。
3. 参数虽然没调，但"选均线族"这个决定本身是看了历史才做的，所以**仍有后视成分**，未来表现大概率不如回测。
4. 与 v1 相比: v1 状态机 BTC 年化 39%、回撤 −48%、需要 5 个阈值；v2 年化 47%、回撤 −49%、零阈值。更简单的赢了，这在量化里很常见。

想复现研究过程: `python research.py` (约 5 分钟)。

### 量能为什么不参与决策 (research_volume.py, 详见 reports/research_volume.md)

专门测了 11 种独立量能策略 + 12 种"量能叠加到均线集成"的变体 + 阈值邻域扫描:

| 结论 | 证据 |
|---|---|
| 量能**确实含信息** | 200 日线上方时, CMF>0.1 的日子未来 60 日均值 BTC +19% / ETH +25%; CMF<0 的日子 +1% / −5%。上涨量占比 >60% 时 20 日胜率 65%, <40% 时 45~49% |
| 但这信息**和价格动量高度重叠** | CMF 与 20 日价格动量相关系数 0.69~0.71, 上涨量占比 0.74~0.75 → 均线已经吸收了大部分 |
| 叠加到策略上**没有一个变体稳定改善** | 12 种变体里, 全程/样本内/样本外三段 Calmar 同时为正的: BTC 仅"加仓需放量 1.5x"一个 (+0.12/+0.10/+0.11), 且该参数在 ETH 上为零效果, 相邻参数 (1.3x / 1.8x) 在 BTC 上转负 → 孤峰 |
| 经典量能理论在币圈**反过来** | "缩量上涨要减仓": 实测缩量上涨后未来 60 日 BTC +14.6% (vs 正常 +10.1%), ETH +27.6% (vs +10.9%)。"OBV 顶背离要减仓": 实测背离后 60 日收益反而更高。这两条规则叠加进去都让策略变差 |
| 单所现货量本身有缺陷 | 不含合约 (币圈主战场)、不含其他交易所, 且 2020 年以来量的结构变化很大 |

所以: 量能在日报里**展示**(量比 / 上涨量占比 / CMF / 顶背离提示), 让你看盘时有参考, 但**不进决策**。加进去只会多几个可以过拟合的参数, 换不来样本外的改善。

## 六、注意

- 这是纪律工具，不是预测工具。程序不会知道 ETF 消息、监管、黑天鹅。
- 强烈建议先**纸面跟踪 1~2 个月**再上真钱，或者只拿一部分仓位跟策略、另一部分死拿，这两种结合往往体验最好。
- 不要因为某一次"它让我卖了结果涨了"就手动干预——趋势策略靠的是几次大趋势赚钱，中间必然有很多小亏损的假信号。
- 加杠杆会把 −48% 回撤变成爆仓。不要加杠杆。
